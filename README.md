# 충남 아마추어 LoL 랭킹

등록된 선수의 솔로랭크 티어를 **하루 한 번 자동으로 긁어와 랭킹표로 보여주는** 사이트입니다.

- 서버 없음 · DB 없음 · **비용 0원** (GitHub Actions + GitHub Pages 무료 범위)
- 수집 대상은 "등록된 선수"뿐이라 크롤러·집계 배치가 필요 없습니다.
- 선수 1명당 하루 2번의 API 호출이 전부입니다.

---

## 동작 구조

```
   [선수]  등록 페이지에서 인증 아이콘 확인 → 아이콘 변경 → 신청서 제출
              │
   [운영자]  Actions 탭 > "선수 등록" 실행
              │  ① Riot ID → puuid 변환      (account-v1)
              │  ② 프로필 아이콘 일치 확인    (summoner-v4)   ← 본인 인증
              ▼
        data/players.json  (승인된 선수 명단, 영구 보관)
              ▲
              ├── (자동 등록을 연결한 경우) 등록 페이지 제출 → Apps Script
              │   → GitHub Actions가 같은 인증을 거쳐 바로 등록
              └── (선수 본인) 정보 수정 페이지 제출 → Apps Script
                  → 그날의 아이콘으로 재인증 → 닉네임·지역·포지션·소속만 변경
              │
   [자동]  매일 04:10 GitHub Actions
              │  ③ 티어 조회                  (league-v4/entries/by-puuid)
              ▼
        data/ranking.json + data/history/YYYY-MM.json  (커밋)
              │
              ▼
        GitHub Pages 정적 페이지 (index.html이 ranking.json만 읽음)
```

호출량: 선수 100명 → 하루 200콜. 개발용 키 한도(2분당 100건)에 맞춰 스스로 대기하므로 약 4분 걸립니다.

## 실제 운영 시작하기 (30분)

### 1. Riot API 키 발급

1. <https://developer.riotgames.com> 로그인 (롤 계정)
2. 메인 화면의 **DEVELOPMENT API KEY** 복사 — `RGAPI-...` 형태
3. 이 키는 **24시간마다 만료**되므로 테스트용입니다. 실운영은 아래 "API 키 관리" 참고.

### 2. GitHub 저장소에 올리기

저장소는 반드시 **Public**이어야 Pages가 무료입니다.
그리고 이 폴더의 **내용물이 저장소 루트**에 있어야 합니다 — `cnrank/`라는 폴더를 한 겹 더
만들면 `.github/workflows/`를 GitHub가 못 찾아서 자동 갱신이 동작하지 않습니다.

```
저장소 루트/
├── .github/workflows/   ← 여기 있어야 Actions가 인식합니다
├── index.html           ← 여기 있어야 Pages 첫 화면이 됩니다
├── css/  js/  data/  scripts/
└── README.md
```

이 폴더에서 그대로 push하면 위 구조가 됩니다.

```bash
git push -u origin main
```

(아직 `git init`을 안 했다면)

```bash
git init
git add .
git commit -m "init: 충남 아마추어 랭킹"
git branch -M main
git remote add origin https://github.com/<아이디>/<저장소>.git
git push -u origin main
```

### 3. API 키 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret**

- Name: `RIOT_API_KEY`
- Secret: 발급받은 키

### 4. Pages 켜기

**Settings → Pages → Source: GitHub Actions** 선택.
`https://<아이디>.github.io/<저장소>/` 로 공개됩니다.

### 5. 첫 선수 등록

**Actions 탭 → 선수 등록 → Run workflow** → Riot ID·이름·소속 입력 → 실행.
아이콘 인증까지 통과하면 `players.json`에 추가되고 랭킹이 바로 갱신됩니다.

## 대회 안내 · 팀 모집

### 대회를 올리려면

`data/events.json` 의 `events` 에 한 칸 추가하면 **대회 안내** 페이지에 뜹니다.
GitHub 웹에서 바로 고쳐도 됩니다.

```json
{ "name": "OO컵 아마추어 대회", "host": "OO협회",
  "start": "2026-10-01", "end": "2026-10-31", "applyBy": "2026-09-25",
  "game": "lol", "url": "https://...", "note": "5인 팀 단위 참가" }
```

- **`end` 가 지나면 '종료'로 바뀌어 기본 목록에서 빠집니다.** 지우지 않아도 됩니다.
  (상태를 '종료'나 '전체'로 바꾸면 다시 보입니다)
- `game` 을 적으면 목록에 종목 표시가 붙습니다 (LoL / VALORANT).
- `applyBy` 가 남아 있으면 "3일 남음"처럼 세어 줍니다.
- **`poster` 는 주최측 허락을 받은 이미지만 넣으세요.** 포스터는 주최측 저작물입니다.
  대회명·기간·주최·링크는 사실 정보라 그냥 적으셔도 됩니다.

### 팀 모집은 디스코드에서

`js/config.js` 의 `discordUrl` 에 초대 링크를 넣으면 **클럽 페이지**에 안내가 뜹니다.
팀을 찾는 사람이 실제로 보는 자리라 거기 한 곳에만 둡니다.
**만료되지 않는 초대 링크**로 만드세요 (디스코드 기본값은 7일 뒤 끊깁니다).

사이트 안에 모집 게시판을 두지 않은 이유는 두 가지입니다.
연락 수단을 저장하면 개인정보를 다루게 되고 **미성년 선수가 섞입니다.**
그리고 글이 쌓이면 신고·삭제·분쟁을 운영자 한 사람이 감당해야 합니다.
사이트는 **누가 어느 지역에 있고 어떤 팀에 속해 있는지**까지만 보여주고,
대화는 디스코드에서 합니다. 클럽 페이지에서 클럽을 누르면 소속 선수가 펼쳐집니다.

## 운영 현황 페이지

사이트 아무 페이지나 맨 아래의 **CHUNGNAM RANK.GG** 버튼을 누르면 열립니다 (`admin.html`).

- 총 등록 인원 · 승인/대기 · ★ 프로 지망 수
- 종목별·지역별 등록 분포
- 등록 명단 (검색·종목·지역·상태 필터)
- **★ 켜기/끄기, 승인/보류를 그 자리에서** 처리

관리 버튼은 기본으로 감춰져 있습니다. 페이지 맨 아래 **운영자 도구**를 누르면 펴집니다.
주소에 `?manage` 를 붙여도 되니, 운영자는 `admin.html?manage` 를 즐겨찾기 해두세요.

> **이 페이지는 누구나 열 수 있습니다.** 서버가 없는 구조라 감출 방법이 없고,
> 감추는 토글도 화면 정리일 뿐 잠금이 아닙니다.
> 다만 보이는 값은 전부 `data/players.json` 에 이미 공개된 것이라 새로 드러나는 정보는 없습니다.
> **바꾸는 일만** 관리 키를 아는 사람이 할 수 있습니다.
> 그래서 화면에는 운영 안내를 적지 않았습니다 — 방문자가 볼 내용이 아니라 여기 적어 둡니다.

### 접속자 수 켜기 (선택)

정적 사이트는 스스로 방문을 셀 수 없어 바깥 도구를 하나 씁니다.
[GoatCounter](https://www.goatcounter.com)를 고른 이유는 **쿠키를 쓰지 않고 개인을 식별하지 않기**
때문입니다. 남는 것은 날짜·페이지·유입 경로 정도이고, 방문자를 사람 단위로 따라다니지 않습니다.
개인 사이트는 무료입니다.

1. goatcounter.com 에서 가입하고 코드를 정합니다 (주소가 `https://cnrank.goatcounter.com` 이면 `cnrank`)
2. `js/config.js` 의 `goatcounter: ""` 에 그 코드를 넣고 커밋

**비워두면 집계 스크립트를 아예 불러오지 않습니다.** 바깥으로 요청이 한 건도 나가지 않습니다.

운영 현황의 '누적 방문' 칸에 숫자를 띄우려면 GoatCounter 사이트 설정에서
**카운터 공개**를 켜세요. 안 켜도 집계는 되고, 그 칸이 대시보드 링크로 바뀝니다.

### 관리 키 준비

Apps Script 프로젝트 설정 → 스크립트 속성에 `ADMIN_KEY` 를 추가하세요.

- **20자 이상 무작위 문자열**을 쓰세요. 짧으면 찍어서 맞힐 수 있습니다.
- 저장소·문서·채팅 어디에도 적지 마세요. 사는 곳은 Apps Script 속성 한 곳뿐입니다.
- 넣지 않으면 **조회는 되고 ★·승인만 잠깁니다.** 그때는 Actions 탭의 `선수 관리`를 쓰세요.
- 입력한 키는 그 탭에서만 기억하고 창을 닫으면 사라집니다 (`sessionStorage`).
- 틀린 시도는 10분에 20회로 제한합니다.

**삭제는 이 페이지에 없습니다.** 되돌릴 수 없는 일이라 Actions 탭의
`선수 관리 → remove` 에만 두었습니다. 선수 본인은 `등록 삭제` 페이지를 쓸 수 있습니다.

## 종목을 하나 더 추가하려면

`js/config.js` 의 `GAMES` 목록에 한 칸을 추가하면 랭킹 페이지에 탭이 하나 늘어납니다.
HTML은 건드릴 필요가 없습니다.

```js
{
  id: "ow", name: "오버워치", short: "OW",
  accent: "#f99e1a", accentHover: "#ffb347",
  status: "preparing",              // 데이터가 준비되면 "live"
  basis: "경쟁전 기준",
  description: "...",
  notice: { title: "...", body: ["...", "..."] },   // preparing 일 때 표 대신 나옵니다
  dataFile: "data/ranking.ow.json",
  positions: [...], tiers: {...}
}
```

- `status: "live"` 로 바꾸려면 `dataFile` 이 실제로 있어야 합니다.
- 랭킹 파일은 **종목마다 하나씩** 둡니다. 티어 체계도 점수 환산도 달라서
  한 파일에 합치면 오히려 복잡해집니다.
  (롤 파일만 이름에 종목이 없는 것은, 지금 돌고 있는 워크플로가 쓰는 경로라서입니다)
- 고른 종목은 주소(`?game=val`)에 남으므로 링크로 공유할 수 있고,
  마지막으로 본 종목을 기억합니다. 단 **아직 열지 않은 종목은 기억하지 않습니다** —
  다음 방문 때 볼 것이 없는 화면으로 착지하지 않도록.
- 등록·수정 페이지는 아직 롤 전용입니다. 인증에 롤 프로필 아이콘을 쓰기 때문인데,

## 운영 방법

| 하고 싶은 일 | 방법 |
|---|---|
| 선수 추가 | Actions → **선수 등록** → Run workflow |
| 승인 보류 / 재승인 | Actions → **선수 관리** → `hold` / `approve` |
| ★ 프로 지망 표시 켜기/끄기 | Actions → **선수 관리** → `pro` / `unpro` |
| 닉네임·지역·포지션 수정 | **선수가 직접** — 사이트의 `정보 수정` 페이지 (운영자 개입 불필요) |
| 〃 (운영자가 대신) | Actions → **선수 관리** → `edit` + 바꿀 항목만 입력 |
| 등록 삭제 | **선수가 직접** — 사이트의 `등록 삭제` 페이지 (종목별/전체) |
| 〃 (운영자가 대신) | Actions → **선수 관리** → `remove` (랭킹·기록에서 전부 삭제) |
| 종목 하나만 해지 | Actions → **선수 관리** → `drop` + 종목 선택 |
| 지금 당장 랭킹 갱신 | Actions → **랭킹 갱신** → Run workflow |
| 사이트 이름·연락처 변경 | `js/config.js` 수정 후 커밋 |

> **티어·전적은 운영자가 바꿀 수 없습니다.** Riot API가 매일 새벽에 자동으로 채웁니다.
> 선수가 직접 정하는 것은 표시 닉네임·지역·주 포지션·소속뿐입니다.

### 선수가 스스로 고칠 수 있는 것

표시 닉네임·지역·주 포지션·소속은 **선수가 `정보 수정` 페이지에서 직접** 바꿉니다.
운영자가 매번 워크플로를 돌릴 필요가 없습니다.

```
정보 수정 페이지 → Apps Script → GitHub Actions → 아이콘 재인증 → 반영 (1~2분)
```

- **아이콘 재인증을 매번 거칩니다.** 남이 남의 정보를 고칠 수 없습니다.
- **수정용 아이콘 번호는 매일 바뀝니다.** 등록용 번호는 Riot ID마다 고정이라,
  인증 후 아이콘을 되돌리지 않은 선수는 Riot ID만 아는 사람에게 정보를 고쳐질 수 있습니다.
  그래서 수정용에는 날짜를 섞습니다 (`edit_icon_id`).
- **하루 한 번**만 가능합니다 (`players.json`의 `lastEditAt`으로 제한).
- 수정 결과는 `ranking.json`에도 바로 반영되므로 **다음 갱신을 기다리지 않아도** 화면이 바뀝니다.
- **Riot ID 변경은 받지 않습니다.** 계정이 바뀌면 `puuid`가 달라져 지금까지의 티어 기록과
  이어지지 않습니다. 운영자가 판단해 처리하세요.
- 잘못 바뀐 값은 Actions → **선수 관리** → `edit` 로 되돌릴 수 있고, 무엇이 언제 바뀌었는지는
  커밋 기록에 남습니다.

### 신청 창구는 둘로 나뉩니다

| | 일반 등록 (`register.html`) | 프로 지망 (`pro.html`) |
|---|---|---|
| 받는 정보 | 닉네임·지역·포지션·소속 | 이름·연락처·이메일 |
| 처리 방식 | **사이트에서 바로 자동 등록** | **이메일로만** |
| 결과 | 랭킹에 등재 | 닉네임 옆 ★ 표시 |
| 보관 위치 | 저장소 (공개) | 구글 드라이브 (비공개) |

프로 지망을 자동 경로에 태우지 않는 이유는 **Actions 실행 기록이 공개**되기 때문입니다.
연락처가 로그에 남으면 되돌릴 수 없습니다. 그래서 이메일로만 받고,
저장소에는 `선수 관리 → pro` 로 ★ 플래그만 켭니다.

## 자동 등록 연결하기 (선택, 무료)

`js/config.js`의 `submitUrl`이 비어 있으면 등록 페이지의 제출 버튼은
**입력값이 채워진 이메일 창**을 엽니다. 운영자가 그걸 보고 워크플로를 돌리면 됩니다.
이것만으로도 운영은 됩니다.

여기에 Google Apps Script를 붙이면 **선수가 제출한 즉시 자동 등록**됩니다.

```
등록 페이지    → Apps Script → GitHub Actions → 아이콘 인증 → 등록 완료 (1~2분)
정보 수정 페이지 → Apps Script → GitHub Actions → 아이콘 재인증 → 수정 완료 (1~2분)
```

GitHub Pages에는 서버가 없어서 브라우저가 저장소에 직접 쓸 수 없습니다.
Apps Script가 그 사이에서 토큰을 보관하는 중계 역할을 합니다. 비용은 없습니다.

설치 방법은 [scripts/apps-script/register-proxy.gs](scripts/apps-script/register-proxy.gs)
파일 맨 위 주석에 단계별로 적어두었습니다. 요약하면:

1. script.google.com에서 새 프로젝트 → 그 파일 내용 붙여넣기
2. 스크립트 속성에 `GITHUB_TOKEN` / `GITHUB_OWNER` / `GITHUB_REPO` 등록
3. 웹 앱으로 배포 (액세스 권한: **모든 사용자**)
4. 나온 URL을 `js/config.js`의 `submitUrl`에 붙여넣고 커밋

토큰은 Apps Script 안에만 있고 사이트에는 노출되지 않습니다.
도배 방지로 하루 접수 수 제한이 걸려 있습니다 (`DAILY_LIMIT`).

> 자동 등록도 **아이콘 인증을 반드시 통과해야** 등록됩니다.
> 남의 Riot ID를 적어 보내면 아이콘이 달라서 실패합니다.

> **이미 연결해 둔 뒤에 이 파일을 고쳤다면 반드시 다시 배포하세요.**
> 붙여넣기만 하면 웹 앱은 옛 버전 그대로 돕니다.
> [배포] → [배포 관리] → 연필(수정) → 버전 [새 버전] → [배포].
> 이렇게 하면 **URL이 유지**되므로 `config.js`는 건드리지 않아도 됩니다.
> ([새 배포]를 누르면 주소가 새로 생겨 `config.js`도 바꿔야 합니다)

## 본인 인증 방식

계정 소유를 API로 증명할 수 있는 유일한 방법이 **프로필 아이콘 확인**입니다.

1. 등록 페이지에서 Riot ID를 넣으면 그 ID 전용 아이콘 번호가 나옵니다
   (`js/verify.js`와 `scripts/riot.py`가 같은 CRC32 해시를 써서 서버 없이도 같은 번호를 냅니다)
   — 정보 수정 페이지는 **날짜가 섞인 다른 번호**를 안내합니다. 아래 표 참고.
2. 신청자가 게임에서 그 아이콘으로 변경
3. 운영자가 등록 워크플로 실행 → `summoner-v4`로 `profileIconId` 대조 → 일치하면 등록

번호를 남이 계산할 수는 있지만, **해당 계정에 로그인해야만** 아이콘을 바꿀 수 있으므로 소유 증명이 됩니다.
아이콘 변경이 API에 반영되기까지 몇 분 걸릴 수 있고, 인증 후에는 원래 아이콘으로 되돌려도 됩니다.

### 등록용 번호와 수정용 번호는 다릅니다

| | 등록 (`register.html`) | 정보 수정 (`edit.html`) |
|---|---|---|
| 번호 계산 | Riot ID만 사용 — **계정마다 고정** | Riot ID + **그날 날짜** — 매일 바뀜 |
| 함수 | `expected_icon_id` / `expectedIconId` | `edit_icon_id` / `editIconId` |

등록은 한 번뿐(중복 Riot ID 거부)이라 고정 번호로 충분합니다.
수정은 반복되는 행위라 사정이 다릅니다 — 인증 후 아이콘을 되돌리지 않은 선수가 있으면
**Riot ID만 아는 사람이 그 선수의 정보를 고칠 수 있게** 됩니다.
그래서 수정용 번호에는 날짜를 섞어, 어제 맞춰둔 아이콘으로는 통과하지 못하게 했습니다.
(자정 직전에 페이지를 열고 자정 직후에 제출하는 경우를 위해 새벽 3시 전까지는 어제 번호도 인정합니다)

> 번호를 두 언어로 각각 계산하므로 어긋나면 **아무도 인증을 통과하지 못합니다.**
> `js/verify.js` 나 `scripts/riot.py` 를 고치면 **아이콘 번호 대조** 워크플로가 자동으로
> 두 결과를 맞춰 봅니다. 수동으로 돌리려면 Actions → 아이콘 번호 대조 → Run workflow.

> "충남 소재"는 API로 확인할 방법이 없습니다. 소속 학교·팀을 받아 **운영자가 수동 승인**하세요.
> (`approved: false`인 선수는 랭킹에 나오지 않습니다)
