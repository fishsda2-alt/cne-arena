# 스타크래프트: 리마스터 종목 추가 — 검토 문서

작성 2026-09-11 · **2026-09-14 구현 완료** — 실제로 택한 방식은 [7. 구현한 방식](#7-구현한-방식-2026-09-14)을 보세요.
아래 1~6은 검토 당시 기록이라, 일부 권고(운영자 승인·유효기간)는 운영 목적에 맞춰 채택하지 않았습니다.

---

## 1. 왜 롤 방식을 못 쓰는가

**블리자드 공식 API에 SC:R이 없습니다.** Battle.net 개발자 API가 다루는 종목은
WoW · 디아블로3 · 하스스톤 · **스타크래프트 II** 까지입니다.

SC:R 래더 엔드포인트 자체는 존재합니다. 다만 `StarCraft.exe` 가 **선수 본인 PC에**
띄우는 로컬 웹서버(`localhost:50250`)를 통해서만 닿습니다. 게임이 실행 중이고
로그인돼 있어야 합니다. GitHub Actions에서는 도달할 방법이 없습니다.

그래서 두 가지가 동시에 막힙니다.

- **자동 티어 수집 불가** — 매일 새벽 배치로 긁어올 대상이 없음
- **본인 인증 불가** — 롤의 프로필 아이콘처럼 API로 확인 가능한 소유 증명 수단이 없음

> Riot(발로란트) 키와는 무관합니다. 회사가 다르고, 어떤 키를 받아도 SC:R은 열리지 않습니다.

## 2. 채택 방향

**자기 신고 + 래더 화면 스크린샷 + 자동 인식(OCR) 보조.**
선수가 제출할 때만 갱신하고, 매일 자동 갱신은 하지 않습니다.

선택지 비교는 [6. 다른 방법들](#6-다른-방법들)에 남겨 두었습니다.

---

## 3. ⚠ 반드시 알고 시작할 것 — 스크린샷은 증거가 아닙니다

**OCR은 "블리자드 서버의 값"을 읽는 게 아니라 "이미지 속 숫자"를 읽습니다.**
그림판으로 숫자만 고쳐도 그대로 통과합니다. 개발자 도구도 필요 없습니다.

여기서 가장 나쁜 조합이 생깁니다.

| | 신뢰도 | 사용자가 느끼는 신뢰 |
|---|---|---|
| 자기 신고 (숫자만 입력) | 낮음 | 낮음 — 정직함 |
| 자기 신고 + 운영자 육안 확인 | 낮음+ | 낮음+ |
| **자기 신고 + OCR 자동 등록** | **낮음 (동일)** | **높음 — 위험** |

OCR을 붙여 자동 등록하면 **아무도 그림을 보지 않게 됩니다.** 육안 확인이 위조를
완벽히 잡지는 못하지만 "이상하면 걸릴 수 있다"는 억지력은 있는데, 자동화는 그것마저
없애면서 *검증된 것처럼 보이는* 인상만 남깁니다. 신뢰도는 그대로인데 신뢰만 올라갑니다.

**그래서 이 설계의 원칙:**

> OCR은 **검증 수단이 아니라 입력 보조**입니다.
> 선수가 숫자를 타이핑하는 수고를 덜어줄 뿐, 승인 판단을 대신하지 않습니다.

### 지켜야 할 세 가지

1. **OCR 결과는 선수에게 보여주고 확인시킵니다.** "이렇게 읽었습니다 — 맞나요?"
   틀리면 손으로 고치게 합니다. 오인식이 조용히 등록되면 안 됩니다.
2. **등록은 운영자 승인을 거칩니다.** 스크린샷은 승인 화면에서 볼 수 있어야 합니다.
   (자동 승인으로 두려면, 아래 4-C의 표기 규칙만은 반드시 지키세요)
3. **롤 티어와 같은 표에 섞지 않습니다.** 자동 수집 값과 자기 신고 값이 한 줄에
   나란히 놓이면, 신고값의 낮은 신뢰도가 롤 티어까지 끌어내립니다.

## 4. 설계안

### A. 스크린샷은 업로드하지 않습니다 — 브라우저에서 인식

```
선수 브라우저
  ├─ 스크린샷 선택 (파일이 사이트를 떠나지 않음)
  ├─ tesseract.js 로 숫자 인식        ← 브라우저 안에서
  ├─ "이렇게 읽었습니다: 1,234위 / MMR 1856" → 선수가 확인·수정
  └─ 숫자만 전송 → Apps Script → GitHub Actions → 등록
```

이미지를 서버로 보내지 않는 편이 모든 면에서 낫습니다.

- **개인정보** — SC:R 래더 화면에는 배틀태그·친구 목록·다른 사람 이름이 같이 찍힙니다.
  공개 저장소에 커밋하면 되돌릴 수 없습니다.
- **크기** — `repository_dispatch` 의 `client_payload` 는 작습니다. 스크린샷(수백 KB~수 MB)을
  base64로 실어 보낼 수 없습니다.
- **비용** — Actions에 Tesseract를 설치하면 실행마다 수십 초가 더 듭니다. 클라우드 OCR은 유료입니다.

단, 운영자 승인을 위해 그림을 봐야 한다면 이미지가 어딘가엔 있어야 합니다.
그때는 **구글 드라이브 업로드 → 링크만 전송**이 현실적입니다. 저장소에는 넣지 마세요.

### B. OCR 정확도에 기대를 걸지 마세요

SC:R 래더 화면은 게임 UI 폰트 + 어두운 배경이라 Tesseract 정확도가 낮습니다.
해상도·창모드·UI 언어에 따라 결과가 제각각입니다.

- 인식 대상을 **숫자만**으로 좁히면(`tessedit_char_whitelist`) 훨씬 안정적입니다.
  한국어 학습데이터도 필요 없어져 가볍습니다.
- **제출 양식을 고정**하세요. "래더 화면 전체를 이 배율로 캡처" 같은 안내와 예시 그림을
  주면 인식률이 크게 오릅니다. 자유 형식은 실패합니다.
- 인식 실패는 정상 경로로 처리하세요 — 못 읽으면 그냥 손으로 입력받습니다.

### C. 화면에는 정직하게 표기

| 항목 | 롤 · 발로란트 | 스타크래프트 |
|---|---|---|
| 출처 | Riot API 자동 수집 | **선수 자기 신고** |
| 갱신 | 매일 04:10 | 선수가 제출할 때만 |
| 표기 | 티어 배지 | 신고 배지 + **제출 날짜** |

- 랭킹표에 `자기 신고 · 9/11 제출` 같은 배지를 답니다.
- **유효기간을 둡니다.** 30일 지나면 "오래된 기록"으로 흐리게, 60일 지나면 목록에서 내립니다.
  안 그러면 1년 전 값이 영원히 1위로 남습니다.
- 종목 탭을 분리해 롤 랭킹과 한 표에 섞지 않습니다.

### D. 본인 인증

롤 계정이 있는 선수라면 **기존 아이콘 인증을 그대로 재사용**할 수 있습니다
(`js/verify.js` / `scripts/riot.py`). Riot 계정과 배틀태그는 별개지만,
"이 사람이 우리 사이트에 등록된 그 선수인지"는 확인됩니다.

롤을 안 하는 선수는 인증 수단이 없습니다. 운영자 수동 확인으로 처리하세요.

## 5. 구조 작업 (데이터만 정해지면 쉬움)

이미 종목별로 나뉘어 있어 손댈 곳이 적습니다.

- `scripts/players.py` — `GAME_NAMES` / `POSITIONS` / `RANKING_FILES` 에 `scr` 추가
- **포지션 대신 종족** — `["테란", "저그", "프로토스", "랜덤"]`. 구조는 그대로 쓰면 됩니다
- `js/config.js` 의 `GAMES` 에 짝을 맞춰 추가
- 점수는 **MMR 또는 래더 순위**를 그대로 정렬 키로 씁니다
  (롤처럼 티어→점수 환산이 필요 없습니다)
- 새 워크플로 `scr-report-from-site.yml` — `repository_dispatch` 로 신고 접수
- `scripts/apps-script/register-proxy.gs` 에 `action: 'scr-report'` 분기 추가
  (고친 뒤 **재배포 필수** — 붙여넣기만 하면 옛 버전이 계속 돕니다)

### 착수 전 체크리스트

- [ ] tesseract.js 가 CDN 허용 목록(cdnjs)에 있는지 확인
- [ ] 학습데이터(`eng.traineddata`) 를 어디서 받을지 — CDN 차단되면 대안 필요
- [ ] 실제 SC:R 래더 스크린샷 5~10장으로 인식률 먼저 측정 (여기서 안 되면 OCR 포기)
- [ ] 제출 양식(캡처 범위·배율) 확정 + 예시 그림
- [ ] 신고값 유효기간 정책 확정 (30일 흐림 / 60일 내림)
- [ ] 운영자 승인을 거칠지, 자동 승인할지 결정

## 6. 다른 방법들

채택하지 않았지만 나중에 사정이 바뀌면 다시 볼 선택지입니다.

| 방법 | 자동 갱신 | 본인 인증 | 비용 | 깨질 위험 |
|---|---|---|---|---|
| **A 자체 리그 Elo** — 지역 대회 결과로 직접 점수 산출 | ○ | ○ | 중 | 없음 |
| **B 자기 신고 (채택)** | ✗ | △ | 소 | 없음 |
| **C 로컬 수집기** — 선수 PC에서 `localhost:50250` 읽어 전송 | △ | ◎ | 대 | 높음 |
| **D 커뮤니티 연계** — cwal.gg 등에 데이터 제공 협의 | ○ | △ | 소 | 상대에 달림 |
| **E 스타크래프트 II** — 공식 API, 롤과 동일 구조 | ◎ | ◎ | 소 | 없음 |

- **A** 는 외부 의존이 0이라 절대 깨지지 않고, 지역 리그를 운영하는 기관 성격과 맞습니다.
  B로 시작했다가 대회가 쌓이면 A로 옮겨가는 경로가 자연스럽습니다.
- **C** 는 인증만큼은 압도적입니다(그 계정으로 로그인해야만 로컬 서버가 뜸). 전면 도입은
  비현실적이지만, **등록할 때 한 번만** 돌리게 하는 용도는 검토할 값어치가 있습니다.
- **D** 는 무단 스크래핑이 아니라 **연락해서 협의**하는 것을 뜻합니다. 지역 아마추어 육성이라는
  목적이 뚜렷해 거절당할 이유가 적습니다. 성사되면 자동 갱신으로 승격할 수 있습니다.
- **E** 는 종목이 SC:R이 아니라는 점만 받아들이면 가장 저렴합니다.

## 7. 구현한 방식 (2026-09-14)

### 운영 목적에 따른 결정

이 기록은 **충남 지역 대회에서 팀을 꾸리고 클럽 활동을 하려고 서로를 알아보는 용도**입니다.
선수 대부분이 30~40대 성인이라 위조 동기가 낮다고 보고, 검토 때 권했던 장치 중 둘을 뺐습니다.

| 검토 때 권고 | 결정 | 이유 |
|---|---|---|
| 인식 결과는 입력 보조로만, 본인 재확인 | **채택** | 인식은 자주 틀림 |
| 스크린샷은 브라우저 안에서만 인식 | **채택** | 개인정보·용량·비용 |
| 롤 랭킹과 한 표에 섞지 않기 | **채택** — 별도 종목 탭 | 롤 표는 손대지 않음 |
| 신고 배지 | **채택** — `본인 등록 / MM.DD.` | 마지막으로 올린 날을 겸함 |
| 운영자 승인 | **안 함** — 제출하면 바로 반영 | 목적상 불필요 |
| 유효기간 (30일 흐림·60일 내림) | **안 함** | 목적상 불필요 |

### 흐름

```
scr.html
  ├─ 스크린샷 고르기 · 붙여넣기(Ctrl+V) · 끌어다 놓기
  ├─ 그림 손보기 (확대/축소 · 흑백 · 어두운 화면이면 반전 · 대비)
  ├─ tesseract.js 5.1.1 (kor+eng) 로 글자 읽기       ← 브라우저 안, 처음 한 번 ~8MB 받음
  ├─ js/scr-parse.js 가 등급·레이팅·승·패·래더 순위를 추려 입력칸을 채움
  │    채운 칸엔 '읽음 · 확인 필요', 못 채운 칸엔 '직접 입력' 표시
  ├─ 선수가 스크린샷과 대조 → "제 스크린샷과 같은지 확인했습니다" 체크 (새로 읽으면 풀림)
  └─ 숫자만 전송 → Apps Script(action: 'scr') → repository_dispatch 'scr-report'
       → .github/workflows/scr-from-site.yml → scripts/scr_report.py
       → data/ranking.scr.json 커밋 → Pages 배포
```

### 파일

| 파일 | 역할 |
|---|---|
| `scr.html` · `js/scr.js` | 스타크래프트 등록 페이지 |
| `js/scr-parse.js` | 인식 글자 → 값 추려내기 (브라우저·node 공용) |
| `scripts/check_scr_parse.js` | 추려내기 시험 — 추출기를 고치면 반드시 실행 |
| `scripts/scr_report.py` | 값 검사 후 반영 · 같은 게임 아이디면 갱신 · `--remove` 로 삭제 |
| `.github/workflows/scr-from-site.yml` | 사이트 접수 반영 + 운영자 수동 삭제(Run workflow) |
| `data/ranking.scr.json` | 실제 기록 (롤 파일과 분리) |
| `data/ranking.scr.sample.json` | `?sample` 미리보기용 가짜 데이터 |
| `js/config.js` | `GAMES` 의 `scr` 칸 — `selfReport: true`, 종족·등급 표, 문구 |
| `js/ranking.js` | `selfReport` 종목만 `rowSelf()` 로 그림. 롤 줄(`row()`)은 그대로 |

### 알아둘 점

- **본인 인증이 없습니다.** 게임 아이디만 알면 누구나 그 기록을 덮어쓸 수 있습니다.
  잘못 올라온 기록은 Actions → **스타크래프트 본인 등록** → Run workflow → 순번(s001)이나 게임 아이디로 지웁니다.
- 기록의 열쇠는 **게임 아이디(대소문자 무시)** 입니다. 아이디를 바꾸면 새 선수로 들어갑니다.
- 매일 갱신은 없습니다. `?player=s003` 공유 링크는 상세 창 대신 그 줄을 짚어 줍니다.
- 롤 등록 페이지(`register.html`)의 종목 선택에는 스타크래프트가 나오지 않습니다.
- 운영 현황의 종목별 막대는 스타크래프트만 `data/ranking.scr.json` 인원으로 셉니다
  (총 등록 인원·승인 수는 `players.json` 기준 그대로).
